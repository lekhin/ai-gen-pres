# Инструкции проекта

## Что это

Фабрика презентаций «для всех»: студент, школьник, офисный работник кладёт
материалы (или просто называет тему) — агент собирает .pptx по теме оформления
(minimal/dark/academic — 16:9, book — книжная A4-полоса), прогоняет аудит, рендерит и **сам** проверяет каждый
слайд. Не корпоративная: дизайн-контур вынесен в темы `_service\themes\`.

## Структура папки

Корень `ai-gen-pres\` — хранилище фабрики. Один проект = одна папка.

- `_service\` — служебная папка (общие ресурсы, НЕ удалять и не перемещать):
  - `themes\<тема>\` — темы оформления: `theme.json` (палитра/шрифты/сетка/qa),
    `template.pptx` (носитель стилей, генерируется из theme.json, руками не править),
    `inspect.md` (дамп шаблона — читать вместо запуска `inspect`).
  - `build.py` — заготовка кодовой сборки python-pptx (копировать в `_build\` проекта).
  - `fonts\` — шрифты тем (Inter; лицензия — `fonts\README.md`).
  - `diagrams\` — галерея эталонов схем (нативные фигуры pptx; см. `diagrams\README.md`).
  - `skills\universal-pptx\` — КАНОНИЧЕСКОЕ место скилла оформления презентаций
    (SKILL.md + `scripts\deck.py …`); `.opencode\skills\` и `.claude\skills\` —
    junction-ссылки на него (создать при переносе:
    `New-Item -ItemType Junction -Path .opencode\skills\universal-pptx -Target <корень>\_service\skills\universal-pptx`, аналогично `.claude\`).
    Книжная вёрстка и метрика набора — `scripts\pptx_book.py` и `scripts\pptx_metrics.py`
    (геометрия полосы из theme.json); регрессия — `scripts\smoke_book.py` + qa.
- `<Имя_Проекта>\` — папка одной презентации:
  - `<Имя_Проекта>.pptx` — готовый файл (в корне папки проекта);
  - исходники/материалы (docx/md/конспекты) — остаются где лежали;
  - `_build\` — служебная подпапка: `plan.json` и/или `build.py`, `facts.md`,
    `render\slideN.png`, вспомогательные скрипты.

Правила: презентацию создавать в папке её материалов; если материалов нет
(режим «из темы») — создать папку `<Тема_презентации>\` и жить в ней; всё
служебное — в `_build\`; общее брать из `_service\`, копии в корень не плодить.

## Переносимость между харнессами
AGENTS.md — единственный источник правил; читают OpenCode, Cline, Codex, Copilot и др.
`CLAUDE.md` и `.clinerules\00-agents.md` — заглушки-ссылки; правки ТОЛЬКО в AGENTS.md.
Команды ниже — от корня фабрики, работают в любом харнессе.

## Режимы входа

1. **Из материалов** (по умолчанию): в задаче указана папка/файлы — содержание
   берётся ТОЛЬКО из них. Веб-поиск подключать, только если в задаче явно сказано
   дополнить/проверить материалами из интернета; без такого указания — молча
   работать по материалам, нехватку помечать как `missing`/`estimate`.
2. **Из темы**: задана только тема («сделай презентацию про круговорот воды,
   8 слайдов») — агент пишет содержание сам по своим знаниям; при явном
   запросе — с веб-поиском. Структура: титул → 4–8 контентных → финал; язык —
   под аудиторию (школьник / студент / офис), без выдуманных фактов (см. ниже).

## Приоритет правил оформления (важно)

Тема оформления (`_service\themes\<тема>\`) **главнее** любых указаний на дизайн
в документах-источниках. Тема выбирается по аудитории (таблица в SKILL.md):
школьный доклад/лекция/отчёт — `minimal`; питч/защита/техдоклад — `dark`;
курсовая/диплом/наука — `academic`; учебник/глава книги/методичка (A4 портрет) —
`book`; если пользователь назвал тему сам — его выбор.
Оформление из источника учитывать ТОЛЬКО если в самой постановке задачи явно
сказано полагаться на дизайн материала или на отступления. Фон слайдов — по теме;
тёмные слайды в светлой теме — только по явному запросу (`"background": "black"`).

## Данные и факты (важно)

На слайды попадают только значения (числа, даты, названия, проценты) со статусом:
- **sourced** — есть в материалах задачи (файлы, текст постановки, web-страница
  при разрешённом веб-поиске — тогда с указанием URL в facts.md);
- **derived** — получено арифметикой из sourced (формула фиксируется в inventory);
- **common_knowledge** — режим «из темы»: общеизвестное из знаний агента
  (планеты Солнечной системы и т.п.) — можно без пометок на слайде;
- **estimate** — значения нет, но ТЗ требует визуал с цифрами: оценка + курсивная
  подпись «оценочно, подлежит уточнению» под визуалом;
- **missing** — требуется, но ставить нечего: плейсхолдер `NNN`/`[уточнить]`
  (выдуманное значение подставлять нельзя).

Приоритет: **материалы задачи > знания агента > желание ТЗ видеть данные**.
Запрещён ложный провенанс: указание источника («по данным NASA», «по выгрузке»)
обязано совпадать с реально существующим материалом/страницей; источника нет —
не указывать. До записи plan.json составить `_build\facts.md`: таблица
`значение | статус | источник`. Финальный ответ обязан содержать приёмочную строку:
**ПРОВЕРКА ДАННЫХ: N значений — sourced/derived X, common_knowledge Y, estimate Z,
missing W; список estimate/missing: …; все указанные на слайдах источники
присутствуют среди материалов: да/нет.**
Строку печатает `deck.py facts <pptx> --facts facts.md` (он же сверяет числа
слайдов с facts.md в обе стороны); часть «источники присутствуют» подтверждает
агент — инструмента для неё нет.

## Рабочий цикл презентации

Единый CLI: `python _service\skills\universal-pptx\scripts\deck.py
themes|inspect|build|mmd|qa|check|render|thumb|make-template|dump|facts …`
1. Тема: выбор по аудитории (см. «Приоритет»); параметры — в SKILL.md, детали —
   `themes\<тема>\inspect.md` (читать вместо запуска `inspect`).
   Материалы (docx/pdf) сначала переводить в текст: `deck.py dump <файл> -o
   <проект>\_build\dump.txt [--media]` — на номера строк дампа ссылается facts.md.
2. Структура: план слайдов и сетка ДО сборки (можно сразу в `plan.json`);
   для «из темы» — сначала facts.md.
3. Сборка: простые/средние слайды — декларативный `deck.py build plan.json`
   (схема — в SKILL.md); экзотика — кодом (заготовка `_service\build.py`,
   хелперы `pptx_helpers.py`); схемы из mermaid — `deck.py mmd`.
4. Аудит ДО рендера: `deck.py qa <pptx> -t <тема>`. Повторять после каждой пересборки.
5. Рендер: `deck.py render <pptx> -o <проект>\_build\render` → `slideN.png` ≤1500 px
   (Windows — PowerPoint COM; вне Windows — soffice→pdf→pdftoppm/PyMuPDF;
   внутренний цикл правок — `--fast` без Office, если установлен ArtCraft).
6. Визуальная проверка каждого слайда (смотреть самой; обзор всех — `deck.py thumb`).
Подробности и грабли — скилл `universal-pptx` (`_service\skills\universal-pptx\SKILL.md`).

## Единицы измерения
Во всех ответах, отчётах и документах — только метрические: см, мм, м, г, кг, °C, л.
Дюймы и прочие имперские переводить по 1″ = 2,54 см (слайд 13,33″ × 7,50″ = 33,87 × 19,05 см).
Исключение — типографская/техническая терминология: кегль в пунктах (pt), dpi, проценты, EMU.

## Язык
Русский (если постановка задачи не требует иного языка презентации).

## Просмотр изображений
У модели есть зрение: PNG/JPG-рендеры смотреть **самой** (`read` на файл), а не
перекладывать визуальную проверку на пользователя. Практика: перед чтением
уменьшать/кроить большие PNG (ширина ≤ 1500 px), крупные листы резать на части.
